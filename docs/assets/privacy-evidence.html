Production fit, without the mythology

Official Deep Agents documentation describes the harness as production-ready. That is not a promise that every workload should use it, or that production controls arrive automatically.

Bottom line: Deep Agents can run in production, but it is an opinionated autonomy harness with planning, filesystems, subagents, memory, summarization, and middleware. Those features increase capability and also expand cost, latency, concurrency, state, and trust boundaries. Use the lighter LangChain create_agent or a custom LangGraph workflow when the full harness does not earn its overhead.
Official guidance

Good fit

Long-running, multi-step work that benefits from planning, context offloading, isolated subagents, durable state, human approval, and rich tool use.

Official alternative

Prefer a lighter agent

Simple assistants and bounded tool loops often need create_agent, fewer middleware layers, fewer processes, and a smaller operational surface.

Architecture decision

Prefer a graph

Deterministic sequencing, strict transitions, predictable latency, regulated approvals, or fixed retry semantics are often clearer as an explicit LangGraph workflow.

Production risk

Autonomy amplifies work

Subagent fan-out and parallel tools can multiply model calls, tool calls, process count, serialized state, failure modes, and spend from one user request.

Security boundary

Tools define authority

Deep Agents follows a "trust the LLM" model. The agent can do what its tools allow, so authorization, sandboxing, and least privilege belong outside the prompt.

Security and complete privacy controls

The gateway minimizes outbound tool results. A production privacy program must protect the entire lifecycle: collection, authorization, processing, storage, disclosure, retention, deletion, audit, and incident response.

Prompt injection remains unsolved by prompting alone. OWASP documents direct, indirect, multimodal, obfuscated, and split-payload attacks. Treat all external content as untrusted, segregate it from instructions, validate model outputs deterministically, minimize authority, and put irreversible or high-impact actions behind human approval.

Production release gate

Do not promote because a demo succeeds. Require recorded owners, thresholds, evidence, and rollback criteria for every gate.

Architecture fit approved

Document why the full harness is needed and why a lighter agent or deterministic graph is insufficient.

Authority is bounded

Inventory tools, scopes, side effects, filesystem/shell access, egress, sandbox rules, and approval points.

Capacity budgets pass

Load-test p95/p99 latency, peak memory, CPU, state, tokens, fan-out, downstream saturation, and cost.

Failure behavior is proven

Exercise timeout, retry, cancellation, duplicate execution, provider outage, tool failure, and checkpoint recovery.

Privacy lifecycle is owned

Approve classification, purpose, residency, retention, deletion, provider terms, passthrough exceptions, and incident response.

Isolation is tested

Test tenant namespaces, memory and checkpoint boundaries, credential separation, session authorization, and cache isolation.

Observability is safe

Alert on latency, errors, cost, policy decisions, and unusual fan-out without copying sensitive payloads into telemetry.

Evaluation is continuous

Run offline regressions and sampled online evaluators for privacy, safety, correctness, and resource-budget violations.
